# 要件定義（ユーザー原文の要約・2026-10-13 受領）

> 原文の意図を保つため、項目は原文どおりに残す。変更が決まったら「決定事項」は CLAUDE.md に書き、ここは原典として残す。

## 目的
税理士試験（簿記論・財務諸表論）の「前提知識」（会計基準の定義・要件・処理の考え方・用語）を
1〜5分の隙間時間に反復学習するアプリ。計算演習は TAC 答練で行い、本アプリは「処理の判断で迷わないための知識」に特化。個人用・非公開。

## 進め方
1. 不明点を質問（最大7個）
2. 技術構成・データ設計・画面一覧・開発フェーズの計画を提示
3. 承認後フェーズ1から実装。各フェーズ終了時に動作確認方法を示して止まる
4. 方針・規約は CLAUDE.md にまとめ、作業のたびに更新

## ユーザー像・利用シーン
- 働きながら受験。スマホ片手、電車内（音なし）、電波が弱い場所
- 1セッション3〜5分、1問10〜30秒。起動から2タップ以内に出題開始
- 答練の直し時間に、間違えた判断ポイントをその場でスマホから登録

## 出題範囲
### 財務諸表論（理論の比重を高く）
- 概念フレームワーク（討議資料）、企業会計原則・注解の一般原則
- 各会計基準の目的・定義・認識/測定の考え方・処理の根拠（収益認識、金融商品、棚卸資産、減損、リース、退職給付、資産除去債務、税効果、純資産・株主資本、包括利益、企業結合、外貨換算、研究開発費、会計上の変更及び誤謬の訂正、時価の算定 など）
- 「なぜその処理をするのか」を問う理由付け問題を重視
### 簿記論（処理の判断基準・要件・用語）
- 例：収益認識の5ステップ、リースの分類要件、減損の兆候→認識→測定と各段階の金額、有価証券の分類ごとの評価基準と評価差額の行き先
- 数値ルール（割合・基準値・期限）は根拠付きでのみ出題

## 出題形式
1. ○× 2. 4択 3. 穴埋め（選択肢タップ式） 4. 複数選択 5. 並べ替え 6. 一問一答フラッシュカード（覚えた/あいまい/忘れた）
- 全問に解説と根拠（基準名・項番号等）を表示。クイック登録分は根拠空でも出題可（未記入と表示）

## 学習ロジック
- 間隔反復（FSRS 推奨、難しければ SM-2）で「今日の復習」
- モード：今日の5問／間違えた問題だけ／答練の間違いだけ／科目・論点別／ランダム
- 論点別の正答率・最終学習日、連続学習日数、1日の目標問題数
- 本試験（例年8月上旬）までの残り日数。試験日は設定で変更可

## クイック登録
- ホームから1タップ、30秒で1問追加
- 必須：科目・論点・問題文・答え・答練名と問題番号
- 任意：形式（既定はフラッシュカード）・解説・根拠（後から追記可）
- 出典区分=答練の間違い、検証ステータス=自作 を自動設定
- 論点は既存リストから候補表示（表記ゆれ防止）
- 登録後すぐ間隔反復の対象
- PC でまとめて解説・根拠を追記・編集できる一覧画面

## 技術要件（代案は理由付きで提案可）
- スマホ優先 PWA（ホーム画面追加・オフライン必須）
- React + TypeScript + Vite、IndexedDB（Dexie 等）
- サーバー・ログイン不要。JSON エクスポート/インポート（クイック登録分を含む）
- 主要ボタンは画面下半分、大きなタップ領域、ダークモード
- 採点・間隔反復・改正チェックのロジックはユニットテスト必須

## 問題データ
- 基本問題はコードと分離し、科目ごとの JSON/YAML
- クイック登録分は IndexedDB、エクスポートで同スキーマ JSON
- 項目：id / 科目 / 論点（大・中・小）/ 形式 / 問題文 / 選択肢 / 正解 / 解説 / 根拠（基準名・項番号）/ 関連基準ID（複数）/ 出典区分（過去問ベース・TAC教材ベース・答練の間違い・オリジナル）/ 出典詳細 / 難易度 / タグ / 検証ステータス（未検証・検証済み・自作・改正により要見直し・除外）/ 最終更新日
- 書き方ガイドとスキーマ検証スクリプト

## 過去問取り込みと改正除外（最重要）
1. standards.json：基準ID / 名称 / 現行版の公表・改正日 / 適用開始時期 / 主な変更点 / 出題範囲か。Claude は下書き、不確かな箇所は「要確認」。確定はユーザーが TAC 情報で行う
2. /reference/past_exams/ の PDF から論点抽出 → standards.json と照合して ✅現行でも同じ / ⚠️改正の影響あり（作り直し案・未検証）/ ❌廃止・範囲外 に分類した一覧を先に提示。出題範囲上の扱いは必ずユーザーに確認。承認後に問題生成
3. standards.json 更新だけで関連問題（基準ID付きのクイック登録分を含む）が「改正により要見直し」に一括切替され出題から外れる

## 正確性・著作権
- 生成問題はすべて「未検証」で登録し区別表示。TAC テキストと照合したものだけ「検証済み」
- 根拠を示せない問題は生成しない
- TAC 教材・答練・過去問の文章を長く写さない。基準・企業会計原則の文言の穴埋めは可
- 初期データは各科目20問程度。仕組みの完成を優先

## 開発フェーズ
- 1：スキーマ、standards.json、○×・4択・フラッシュカード、セッションの流れ、クイック登録、端末保存
- 2：間隔反復、今日の復習、間違い／答練の間違いモード、PWA/オフライン
- 3：過去問PDF→論点抽出→改正チェック→分類一覧→問題生成ワークフロー
- 4：穴埋め・複数選択・並べ替え、論点別成績、クイック登録問題の一括編集、エクスポート/インポート

## 完成の定義
- 2タップ以内に出題、5問を2分以内
- 答練の間違いを30秒以内に登録、翌日以降の復習に出る
- 機内モードで解け、履歴と登録問題が残る
- 問題ファイルの追加・編集だけで出題に反映
- standards.json に改正を反映すると影響問題が自動で出題から外れる
